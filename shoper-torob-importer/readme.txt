با نوشتن نام محصول یا چسباندن لینک ترب، اطلاعات کامل محصول (نام، توضیحات، گالری تصاویر و تمام مشخصات فنی به‌صورت ویژگی‌های مجزا) را از ترب دریافت و یک محصول کامل ووکامرس بسازید.

== توضیحات ==

Shoper (شاپر) یک ابزار ساخت خودکار محصول برای ووکامرس است که به ترب (Torob) متصل می‌شود.

= ویژگی‌ها =

* جستجوی محصول با **نام محصول** (روش اصلی و پیش‌فرض).
* پشتیبانی از **لینک مستقیم** محصول در ترب.
* نمایش **پیش‌نمایش** کامل محصول قبل از ساخت.
* دانلود خودکار **گالری تصاویر** به کتابخانه‌ی رسانه‌ی وردپرس و اتصال به محصول.
* افزودن **همه‌ی مشخصات فنی به‌صورت ویژگی‌های مجزا** در تب «ویژگی‌ها» (هر مشخصه مانند پردازنده، وزن، نوع شنا، یک ویژگی مستقل).
* ثبت قیمت ارزان‌ترین فروشنده.
* جلوگیری از ساخت محصول تکراری (SKU بر اساس شناسه‌ی ترب).
* امکان ویرایش عنوان و توضیحات قبل از ساخت.
* دکمه‌ی اختصاصی در صفحه‌ی افزودن/ویرایش محصول برای پر کردن سریع.
* حالت داده‌ی نمونه (Mock) برای تست بدون نیاز به اتصال.
* سازگار با HPOS ووکامرس.

== نصب ==

1. پوشه‌ی `shoper-torob-importer` را در مسیر `wp-content/plugins/` آپلود کنید.
2. افزونه را از صفحه‌ی «افزونه‌ها» فعال کنید.
3. از منوی «ووکامرس ← Shoper (از ترب)» استفاده کنید.

== سؤالات متداول ==

= آیا نیاز به کلید API ترب دارم؟ =
خیر. افزونه از API عمومی وب‌اپلیکیشن ترب استفاده می‌کند.

= آیا باید هاست من به ترب دسترسی داشته باشد؟ =
بله. اگر هاست شما نتواند به api.torob.com متصل شود (مثلاً هاست خارج از ایران)، می‌توانید در آینده از یک سرویس واسط استفاده کنید. در صفحه‌ی افزونه دکمه‌ی «تست اتصال» وجود دارد.

= تصاویر کجا ذخیره می‌شوند؟ =
همه‌ی تصاویر ابتدا با `media_sideload_image` دانلود و در کتابخانه‌ی رسانه‌ی وردپرس ثبت می‌شوند، سپس به‌عنوان تصویر شاخص و گالری به محصول وصل می‌شوند.

= مشخصات فنی چطور ثبت می‌شوند؟ =
هر مشخصه‌ی فنی (مثلاً «پردازنده»، «وزن»، «نوع شنا») به‌صورت یک **ویژگی (Attribute) مجزا** در تب ویژگی‌های محصول ثبت می‌شود — درست همان‌طور که خواسته بودید.

= 1.3.2 =
* بررسی نسخه ۱.۲: لیست از مسیر سرور می‌آمد؛ کلیک به‌خاطر نفرستادن more_info_url خالی می‌ماند.
* درگاه پیش‌فرض تست‌شده (CORS.SH) وقتی ترب IP هاست را با کد ۴۹۰ مسدود کند.
* پروکسی‌های باز تصادفی اضافه نشدند؛ فقط درگاهی که JSON معتبر برگرداند پیش‌فرض شد.
* نوار پیشنهاد دیگر خطای واقعی اتصال را قایم نمی‌کند.

= 1.3.1 =
* عیب‌یابی دیگر مسدود بودن سرور (۴۹۰) را به‌اشتباه «خرابی افزونه» نشان نمی‌دهد و مسیر مرورگر را هم می‌سنجد.
* فیلد روش دریافت و رله ایران در تنظیمات؛ دکمه دانلود فایل رله.

= 1.3.0 =
* رفع قطعی کار نکردن افزونه وقتی ترب کد ۴۹۰ (کپچا) برمی‌گرداند:
  * بارگذاری کلاس تجمیع فروشندگان که در ۱.۲.۲ جا افتاده بود و کل جستجو/پیشنهاد را از کار می‌انداخت.
  * دریافت داده از مرورگر کاربر (مناسب هاست خارج از ایران) و ساخت محصول از همان JSON بدون تماس دوباره با ترب.
  * اگر جزئیات مسدود شود، پیش‌نمایش از نتیجهٔ جستجو ساخته می‌شود تا کلیک روی پیشنهاد دیگر بی‌اثر نباشد.
  * تنظیم رلهٔ ایران (`tools/shoper-relay.php`) و پروکسی خروجی برای WordPress HTTP API.
* عبور دادن `more_info_url` هنگام انتخاب پیشنهاد نام.

= 1.2.2 (اصلاح‌شده) =
* رفع ریشه‌ای مشکل اتصال به ترب:
  * بازنویسی لایه‌ی HTTP — cURL فقط در صورت وجود استفاده می‌شود و در صورت شکست به‌صورت واقعی به WordPress HTTP API برمی‌گردد.
  * حذف Brotli از Accept-Encoding (فقط gzip/deflate) و فعال ماندن SSL verification.
  * timeout و connect-timeout جداگانه؛ تلاش مجدد با backoff واقعی برای 429/502/503.
  * پاسخ غیر 2xx هرگز به‌عنوان JSON موفق پردازش نمی‌شود.
  * خطای شبکه هرگز به «بدون نتیجه» تبدیل نمی‌شود؛ فقط پاسخ موفق کش می‌شود.
* بازیابی نوار کشویی پیشنهاد (autocomplete) که در 1.2.2 از کار افتاده بود.
* اصلاح پارامتر جستجو به «q» (پارامتر نادرست «query» حذف شد).
* جزئیات محصول: درخواست اصلی فقط با `prk` و `source=next_desktop`؛ `more_info_url` و `details-log-click` فقط fallback.
* پیام‌های خطای مجزا در رابط کاربری (شبکه، ترب، JSON، nonce، دسترسی).
* افزودن لاگ اشکال‌زدایی قابل فعال/غیرفعال‌کردن (گزینه یا ثابت `SHOPER_DEBUG`).
* افزودن دکمه‌ی «عیب‌یابی کامل»: اجرای همه‌ی بررسی‌های اتصال (DNS، cURL با/بدون فشرده‌سازی، Brotli مقایسه‌ای، WordPress HTTP API، User-Agentهای مختلف، پروکسی) و نمایش گزارش کامل قابل کپی برای ارسال به پشتیبانی.
